Chapter 1

1 Mental model

A workflow execution is an append-only event log plus a materialized projection of it. Workers never mutate state. They receive history, run deterministic code over it, and return commands. The server turns accepted commands into events.

Invariant History events, mutable state and the tasks derived from them are committed in one persistence transaction per shard (SQL: one DB transaction; Cassandra: one LWT batch conditioned on the shard's range_id). A shard that loses ownership fails its next write with a range-ID mismatch. This fencing is the only mechanism that prevents split-brain writers.

1.2 Identity of an execution

namespace
Tenant boundary. The client sends the name; the server resolves it to namespace_id, a UUID stored as BINARY(16) in SQL and as a 36-char string inside protos. Specimen: default → 73ab11db-a831-4574-b804-b43fedd412e7.
workflow_id
User-chosen business key, at most limit.maxIDLength = 1000 characters. There is at most one open run per (namespace, workflow_id). The current_executions row enforces this.
run_id
Server-generated UUID, version 7 in current servers ({{T:common/primitives/uuid.go#L69-L77}}). Specimen 01a0e5b9-57dd-72b4-be73-4a740836a44e: its 48-bit millisecond prefix 0x01a0e5b957dd = 1790560524253 ms, which matches event 1's event_time (1790560524.253178261 s).
first_execution_run_id
Run ID of the first run in a continue-as-new or retry chain. Carried in the start event (#16) and in WorkflowExecutionState (#8).
request_id
Client idempotency key. Specimen 35131bbf-… is persisted as create_request_id and in the request_ids map (→ event_type 1, event_id 1), so a retried StartWorkflowExecution returns the same run.

1.5 Specimen timeline

All 16 events of the specimen appear below, with offsets from event 1, task IDs, encoded sizes and the history_node batch that holds each one. The batch sizes add up to exactly 1541 B, the value the server stores as execution_stats.history_size and reports as HistorySizeBytes in DescribeWorkflowExecution.

Observe A first-attempt WFT costs three events: SCHEDULED, STARTED and COMPLETED. STARTED is always a batch of its own (nodes 3, 9, 14) because RecordWorkflowTaskStarted runs when Matching dispatches the task, in a transaction separate from the worker's reply. A retried WFT (attempt > 1) is transient. Its SCHEDULED and STARTED events are not persisted. They reach the worker as a history suffix (TransientWorkflowTaskInfo.history_suffix, {{T:proto/internal/temporal/server/api/history/v1/message.proto#L10-L16}}), so a crash-looping workflow does not grow its history.

Appendix D

D Glossary

Activity
Non-deterministic unit of work executed by a worker. Scheduled by command, retried by server policy.
Branch / tree
History storage topology: a tree per first run, branches per reset or conflict fork (§4.1).
Buffered event
External event held while a WFT is in flight, then flushed after completion (§4.3).
CHASM
The server's component-tree state framework. Archetype IDs are farm fingerprints of component names (§8.4).
Command
Worker → server instruction in a WFT completion (§1.3).
Current execution
The single open (or most recent) run for a workflow ID. Row in current_executions.
DataBlob
{encoding_type, data} wrapper for every persisted proto (§2.5).
Eager execution
Activity task (or first WFT) returned inline in an RPC response instead of via matching (§7.5).
Failover version
Per-event int64 encoding which cluster wrote it (§6.4).
Marker
MARKER_RECORDED event storing SDK-level non-determinism (version, side effects, local activities).
Mutable state
Materialized projection of history used for decisions (§5.1).
Namespace
Isolation and configuration unit. Name for clients, UUID internally.
Partition
Sub-queue of a task queue owned by one matching host. Default 4 (§5.4).
Payload
{metadata, data} carrier of every user value (§3.3).
Range ID
Shard or partition ownership epoch, used for fencing and task-ID ranges (§2.3).
Shard
Unit of history ownership and transactionality. fp32(nsID_wfID) mod N + 1.
Speculative WFT
WFT for an update, not persisted unless it produces events (§8.3).
Sticky queue
Worker-private queue host:uuid used while its cache holds the workflow (§7.5).
Task (history)
Outbox record in a shard queue category (§5.6).
Task token
Serialized token.v1.Task the worker echoes back on respond (§7.4).
Transient
Events not yet persisted: activity started (−124) or retried WFT events.
WFT
Workflow task: one round of "give the worker new history, get commands back".

Appendix F

F Reproducing the specimen

# 1. server @ d8f9c6d8 (1.33.0)
git clone https://github.com/temporalio/temporal && cd temporal
go build -o temporal-server ./cmd/server
sed -e 's/numHistoryShards: 1/numHistoryShards: 4/' \
    -e 's#databaseName: "default"#databaseName: "/abs/path/temporal.db"#' \
    config/development-sqlite-file.yaml > run/config/development.yaml
cp -r config/dynamicconfig run/config/
./temporal-server --config-file run/config/development.yaml --allow-no-auth start

# 2. worker + capture (this repo: tools/probe/main.go, built inside sdk-go @ 626130f1)
go run ./cmd/probe          # registers "default", runs OrderWorkflow, dumps RPC bodies

# 3. annotate (this repo: tools/annot/main.go, built inside the server module)
./annot temporal.api.history.v1.History hnode_01.bin     # → JSON spans

# 4. descriptors and the manual
./desc temporal.api.common.v1.Payload … > data/structs.json
python3 tools/build.py      # → temporal-technical-manual.html

Timestamps, UUIDs, build IDs and the pid in identity will differ between runs. Byte layouts, field numbers, sizes of fixed-width parts and derivation rules will not, as long as the pins match.
